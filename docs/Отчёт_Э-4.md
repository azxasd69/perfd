## 1. Что сделано

### 1.1 Схема БД (миграция 002, добавляющая)

| Объект | Назначение |
|---|---|
| `stand_generations` | поколение стенда по отпечатку среды; `parent_generation_id` связывает смену железа |
| `results`, `history` | перестроены на `generation_id`; старые строки перенесены (1 стенд = 1 поколение) |
| `aggregates` | ключ `(generation_id, base_generation_id, formula)` + лучший/худший сценарий и дата замера |
| `history_monthly` | месячные свёртки, бессрочно (ТЗ Р-19) |
| `scenarios` | справочник кодов: представление, единица, порция |
| `audit_log`, `tokens` | след операций и токены с ролями (ingest/read/admin) |
| `ingest_log` | + `channel`, `body_sha256`, `issue`, `generation_id` |
| `stand_passports` | + `generation_id`, `body_sha256`, `is_current` |

Миграция идемпотентна: повторный запуск службы оставляет схему на версии 2 (проверено).

### 1.2 Приём конвертов

Единый конвейер `store.Ingest()` — одна точка вызова для всех транспортов (ТЗ Р-01): HTTP-обработчик, `-watch`, `-import` передают конверт в одну и ту же функцию.

| Правило | Код | Проверено |
|---|---|---|
| нет токена | 401 | да |
| роль не ingest/admin | 403 | код есть, тестом не покрыт |
| тело > 256 КиБ, батч > 50 | 413 | лимиты в `/meta` |
| `schema != 1` | 415 | да |
| повтор `id` + тот же хеш | 200 `duplicate` | да |
| тот же `id`, другое тело | 409 `conflict` | да (юнит-тест) |
| часть конвертов битая | 207 + `items[]` | да |
| битый JSON, пустой батч | 400 | да |

Транзакция — на конверт: отказ одного не откатывает остальные. Замеры пишутся в `results` (upsert по `generation_id, scenario`) и `history` (`DO NOTHING` по времени).

### 1.3 Формула ИИ

`100 × среднее(per_unit_ms базы / per_unit_ms стенда)` по парным сценариям, округление до 1 знака.
Проверка: три пары 0,5 / 1,0 / 0,8 → **76,7** и локально, и на контуре; парных сценариев 3.

База сравнения выбирается по ключу стенда (вхождение «ендор»), иначе индекс 0 — это видно в карточке. Порог «< 5 сценариев» — только признак `low_data`, на расчёт не влияет (как в 1С).

### 1.4 Страницы и API

Страницы: `/perf/` (дашборд), `/perf/stands`, `/perf/stands/{slug}` (карточка: ИИ, сценарии с дельтой, поколения, паспорт), `/perf/stands/{slug}/history/{scenario}`, `/perf/top`, `/perf/about` (методика).

API: `meta`, `stands`, `stands/{slug}`, `stands/{slug}/results`, `stands/{slug}/history?scenario=&granularity=day|month`, `top`, `ratings`, `compare`. Служебные: `healthz`, `readyz`, `healthz/channels`, `metrics` (счётчик `perfd_ingest_total`).

### 1.5 Файловый приёмник (`-watch`)

`in/*.json` → разбор → `Ingest` → `out/<id>.ack` (или `.err`) → `archive/<дата>/`.
Проверено на контуре: подтверждение `{"status":"ok","code":200}`, файл в архиве, `ingest_log.channel='webdav'`, стенд и замер появились.

### 1.6 Обслуживание

- `-retention`: свёртка полных месяцев старше окна в `history_monthly`, **проверка** «свёрнуто ≥ строк», только потом удаление; журнал приёма — по сроку; `PRAGMA incremental_vacuum`. Порядок проверен юнит-тестом: без свёртки удаление не выполняется.
- `-export`: `VACUUM INTO` → gzip → манифест (SHA-256, счётчики, версия схемы). На контуре: 7 КБ, счётчики совпали.
- `-check`: открывает базу **только на чтение** (`mode=ro`), поэтому проверка снимка не требует прав записи.

## 4. Отступления от ТЗ и почему

1. **`stands.id` — TEXT (slug), а не INTEGER.** Стендов десятки, ссылки читаемее; `generation_id` INTEGER выполняет роль числового ключа.
2. **База сравнения — по вхождению «ендор» в ключ стенда.** В ТЗ база задаётся конфигурацией; пока 1С присылает ключи вида `KOMP-832732-22-64-F`, признак «вендор» — единственный доступный. Когда появится явный флаг в паспорте, выборка меняется одной функцией `baseGeneration`.
3. **HMAC не проверяется.** Токен в заголовке — единственная проверка подлинности; поле `sig` принимается (`none`), но не валидируется: прикладного шифрования и подписи нет по решению О-05/Р-21.
4. **`visibility` по умолчанию `private`** — публично витрина пуста, пока не выставлено `public`. Это соответствует ТЗ, но для демонстрации нужен токен чтения.
5. **Транспорты 5б/6/7/8 не разворачивались** (vsftpd, postfix/dovecot, `sshd Match`, DNS-приёмник): файловый приёмник готов их принять, но сами службы и их конфиги — следующий этап.
6. **Отдельных юнитов `app-perfd-watch/-mail/-dns/-alerts` нет:** `-watch` запускается вручную. Юнит добавляется одной строкой `ExecStart=/usr/local/bin/perfd -watch` + `EnvironmentFile`.

## 5. Остаточный риск

- **R-1. Строгий `id`.** Регэксп `^(r|p|h)-[A-Za-z0-9_-]{43}$` отвергнет конверт с другим форматом: 1С-сторона должна генерировать именно так (ТЗ § 7.2). Не подтверждено на реальной выгрузке.
- **R-2. Эвристика базы.** Если в парке не будет стенда с «ендор» в ключе, все индексы будут 0 — это видно, но выглядит как «нет данных».
- **R-3. Нет приёма по 443 без nginx.** Приложение слушает только loopback: при падении nginx приём недоступен, 1С получит 502 и будет повторять (идемпотентность защищает).
- **R-4. Проверено на синтетике.** Конверты формировал смоук-скрипт, а не 1С 1.22: реальные имена сценариев, порции и паспорт (71 реквизит) пройдут проверку только живым прогоном.
- **R-5. Один сценарий отказа БД не проверялся** (переполнение диска, повреждение файла): `/healthz` отдаст 503, `readyz` покажет место, но деградация приёмa не тестировалась.

### 8.3 Грабли, которые стоили времени

1. `ssl_tlsv1_3=YES` и `ssl_tlsv1_2=YES` в vsftpd 3.0.5 — молчаливый `rc=2`, ни строки в journal. Искать пришлось поштучной проверкой параметров.
2. `master.cf`, собранный «по минимуму», ломает smtpd: `proxymap` нужен даже для локальной доставки.
3. Вложение JSON от Python-клиента приходит в base64 — поллер обязан снимать `Content-Transfer-Encoding`, иначе `bad_json` на каждом письме.
4. `bind --bind` поверх существующей точки монтирования молча оставляет старый источник: проверять `mountpoint` и перемонтировать явно.
5. `chmod 750` на `/var/mailvhost` отрезал доставку: postfix запускает `local(8)` без дополнительных групп.

### 8.4 Что осталось

- **DNS**: сквозной приём возможен только после делегирования подзоны (О-08); сейчас проверено `dig +tcp` и полный цикл TXT-частей с локального адреса.
- **Проверка после перезагрузки** не выполнялась: юниты `enabled`, строки bind — в `/etc/fstab`, но фактический ребут контура не делался.
- **Алерты**: `-metrics-addr` принимается, но отдельный HTTP-порт метрик в режиме `-alerts` ещё не поднят.
- **fail2ban**: три jail из ТЗ (`perf-ingest`, `perf-ftp`, `perf-imap`) не включались — фильтры не проверены на реальных логах.
## 9. Одностраничник состояния сервера (08.11.2026, 10:25–10:35)
